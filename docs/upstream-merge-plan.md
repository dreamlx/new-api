## 🎯 合并原则

1. **增量式更新**：分阶段合并，每阶段验证后再继续
2. **保护自定义功能**：确保外部用户API、Token回调等功能完整

## 🛠️ 冲突解决策略

### 策略1: 保留双方（推荐）
适用于：新增字段、新增路由
```
我们的修改 + 上游修改 = 合并后代码
```

### 策略2: 以我们为主
适用于：核心业务逻辑修改
```
如果上游修改与我们的功能冲突，优先保留我们的实现
```

### 策略3: 以上游为主
适用于：Bug修复、性能优化
```
如果上游是明确的Bug修复，采用上游版本
```

## 📋 执行步骤

### 准备工作
```bash
# 1. 创建测试分支
git checkout -b merge/upstream-v0.10.4

# 2. 确保上游最新
git fetch upstream
```

### 阶段执行模板
```bash
# 合并目标版本
git merge v0.9.9 --no-edit

# 如果有冲突
git status  # 查看冲突文件
# 手动解决冲突
git add .
git commit

# 验证
go build -o /tmp/test-build .
make test-api  # 如果有测试
```

### 回滚方案
```bash
# 如果某阶段失败，回滚到上一个稳定点
git reset --hard HEAD~1
# 或回滚到main
git checkout main
git branch -D merge/upstream-v0.10.4
```
