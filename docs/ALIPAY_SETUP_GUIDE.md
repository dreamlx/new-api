# 支付宝直连支付配置指南

> 适用于 nеw-аρi（QuаntumΝоuѕ）后台运营人员 / 站点管理员。

## 1. 概述

本指南介绍如何为 nеw-аρi 启用 **支付宝直连支付** 通道。该通道使用支付宝开放平台官方 SDK（基于电脑网站支付 PC 网页支付能力），由商户私钥/支付宝公钥进行 RSA2048 签名校验，直接与支付宝开放平台通信。

适用场景对比：

- **支付宝直连**（本指南）：商户独立接入，资金直接进入商户支付宝账户；签名密钥、回调、对账完全由 nеw-аρi 系统处理；适合已有支付宝商户资质的站点。
- **易支付（epay）通道**：通过第三方聚合支付平台中转，配置简单但有手续费抽成、资金需 T+N 结算；适合个人站长尚未办理商户的场景。

如果你已经有支付宝商户账号并完成了网站应用的实名/资质审核，**推荐使用本指南的直连方案**。

## 2. 前置条件

请在开始之前确认以下事项：

1. 已注册的 **支付宝商户账号** 或 **支付宝开放平台账号**（[open.alipay.com](https://open.alipay.com/)）。
2. 已在开放平台创建并通过审核的 **网页&移动应用**（控制台 → 应用列表 → 网页&移动应用）。
3. 服务器需具有 **公网可达的 HTTPS 域名**——支付宝异步通知 (notify_url) 必须能从公网访问，HTTP 在生产环境不被推荐。
4. 已生成一对 **RSA2048 应用密钥**（推荐使用支付宝开放平台密钥工具）。
5. nеw-аρi 部署完毕，**系统设置 → 通用设置 → 服务器地址** 已正确填写（用于自动拼接通知地址）。

## 3. 沙箱环境测试

正式商户接入前，强烈建议先在沙箱中跑通完整流程。

1. 访问 [支付宝开放平台沙箱](https://openhome.alipay.com/develop/sandbox/app)，获取沙箱专属的：
   - **沙箱应用 AppId**（注意：与正式 AppId 完全不同，前缀通常以 `9021` 开头）
   - **沙箱应用私钥 / 支付宝公钥**
   - **沙箱买家账号**（用于扫码登录，金额可任意）
2. 在 nеw-аρi 后台 → **系统设置 → 支付设置 → 支付宝** 面板中：
   - 填入沙箱专属凭证。
   - 勾选 **沙箱模式** Switch。
   - 暂时调低 **最低充值数量** 便于测试（如 1）。
   - 保存并启用 **支付宝支付** Switch。
3. 在用户充值页发起一笔小额订单 → 用沙箱买家账号扫码 → 验证：
   - 同步跳转回 nеw-аρi 充值页。
   - 几秒后通过 `/api/user/topup/status` 轮询确认订单变为 `success`。
   - 用户额度成功到账。

测试通过后，切换为正式环境凭证并 **关闭沙箱模式** 开关。

## 4. 配置步骤

### 4.1 在支付宝开放平台创建/确认应用

1. 进入 [open.alipay.com](https://open.alipay.com/) → 控制台 → 网页&移动应用。
2. 找到（或新建）你的应用，记下 **AppId**（16 位数字字符串）。
3. 在应用详情 → **开发设置 → 接口加签方式**：
   - 选择 **公钥模式**（RSA2048）。
   - 使用支付宝官方密钥工具生成 **应用私钥 / 应用公钥** 对。
   - 上传 **应用公钥** 到支付宝。
   - 平台会返回 **支付宝公钥**——立即下载或复制保存。
4. 在 **能力管理** 中确认已开通 **电脑网站支付 (alipay.trade.page.pay)** 能力。
5. （可选）在 **开发设置 → 接口内容加密方式** 处暂时无需开启（本系统使用签名校验已足够）。

### 4.2 在 nеw-аρi 后台填写配置

进入 **管理后台 → 系统设置 → 支付设置 → 支付宝**，按下列字段填入：

| 字段 | 说明 |
| --- | --- |
| **应用 AppId** | 支付宝开放平台应用 AppId |
| **应用私钥** | 应用私钥的 PEM 内容，需带 `-----BEGIN RSA PRIVATE KEY-----` / `-----END RSA PRIVATE KEY-----` 头尾 |
| **支付宝公钥** | 从开放平台下载的支付宝公钥 PEM 内容，需带 `-----BEGIN PUBLIC KEY-----` / `-----END PUBLIC KEY-----` 头尾 |
| **Seller ID（可选）** | 商户 PID，可留空；填入后系统会在异步通知中额外校验 `seller_id`，多一层防伪 |
| **最低充值数量** | 触发支付宝按钮的最低充值数量，例如 1 |
| **沙箱模式** | 调试时开启，正式环境务必关闭 |
| **启用支付宝支付** | 总开关，关闭后用户充值页不显示支付宝按钮 |

> 私钥/公钥字段是 **敏感信息**。后端会对返回值做掩码处理（仅显示 `***xxxx`），刷新页面后无需重新填写，留空即视为沿用已保存的值。

最后点击 **更新支付宝设置** 保存。

## 5. 回调地址

支付宝直连支付涉及两个 URL，**两者都应在开放平台应用配置中预先登记**（如开放平台要求）：

| 用途 | URL 模板 |
| --- | --- |
| 异步通知 (`notify_url`) | `<服务器地址>/api/user/alipay/notify` |
| 同步跳转 (`return_url`) | `<服务器地址>/api/user/alipay/return` |

其中 `<服务器地址>` = **系统设置 → 通用设置 → 服务器地址**（自动去除末尾斜杠）。

**异步通知** 是订单成功的权威来源：支付宝在用户支付完成后会向该地址发起 POST，nеw-аρi 验签后将订单标记为 `success` 并发放额度。同步跳转仅用于用户视觉体验，不能作为成功凭据。

## 6. 常见问题

### 6.1 验签失败 / 公钥不匹配

- 检查 **应用私钥** 与上传到开放平台的 **应用公钥** 是否为同一对密钥；
- 检查填入 nеw-аρi 的 **支付宝公钥** 是否来自当前应用（沙箱与正式环境的公钥不同）；
- PEM 内容必须包含完整 BEGIN/END 标记，且换行符为 `\n`；
- 切换沙箱/正式模式后必须同时切换三组密钥（AppId / 应用私钥 / 支付宝公钥）。

### 6.2 异步通知未到达

- 排查服务器防火墙：异步通知来源 IP 不固定，应放开 `0.0.0.0/0` 对 `/api/user/alipay/notify` 的入站；
- 确认 HTTPS 证书有效（不能为自签）；
- 确认域名 DNS 已正确解析；
- 查看 nеw-аρi 系统日志，若没有任何 `alipay notify` 入站记录，说明请求未到达本机；
- 如长时间未收到通知，可由用户主动发起 **「查询订单状态」**（前端轮询会触发 `/api/user/topup/status` 兜底）。

### 6.3 沙箱与正式环境混淆

- 沙箱与正式环境的 AppId / 密钥完全独立，不可混用；
- 切换环境时同步切换 **沙箱模式** Switch；
- 沙箱订单不能在正式环境查询，反之亦然。

### 6.4 金额不一致 / 货币错乱

- 支付宝直连金额单位为人民币 **元**，nеw-аρi 内部将充值数量按系统配置换算为价格；
- 异步通知中的 `total_amount` 会与本地订单的 `amount` 进行严格比对，不一致会被标记为 `anomaly`；
- 如出现 `anomaly` 状态，请检查 **充值价格** 配置是否在订单创建后被改动。

## 7. 退款流程（摘要）

支付宝直连支付的退款是 **同步** 的：调用支付宝 `alipay.trade.refund` 接口，返回 `code === 10000` 即代表退款成功。

操作流程：

1. root 管理员登录后台 → **用户管理 → 充值历史**，或从用户详情页打开充值记录；
2. 选中目标订单 → 点击 **退款** → 弹出二次确认对话框；
3. 系统会颁发一个 **5 分钟有效的 confirm_token**，需在窗口内输入或自动填充确认；
4. 提交后系统调用支付宝退款接口：
   - 成功：订单 `refund_status` 立即变为 `success`，用户额度同步扣除；
   - 失败：订单 `refund_status` 标记为 `failed`，记录失败原因，可重试。

> 注意：退款会从用户当前余额中扣减相应额度，若用户余额不足会扣至负值（由系统策略决定）。请确保运营流程中对负额度有处置规则。
